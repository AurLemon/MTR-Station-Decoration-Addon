[English](README.md)

Minecraft Transit Railway Mod 的一个车站装饰扩展模组，本仓库是从[AIDA64S/MTR-Station-Decoration-Addon](https://github.com/AIDA64S/MTR-Station-Decoration-Addon) Fork 而来的项目。

我（或者更准确地说是 GPT + Claude 等多个 LLM 配合帮我改的，我只负责测试和指挥它们，哈哈）只能尽量使 MSD v1.3.4 版本**同时兼容 MTR 3.2.2 和 Minecraft 1.20.1 版本**。

如果您发现任何 bug，请在本仓库提交 Issue 而非原仓库，尽量修复（如果我们会修）。

欢迎提交 PR！同时我们也正在尝试其他别的适配，比如让**伦敦地铁 MTR 扩展**也做到同时兼容 MTR 3.2.2 和 Minecraft 1.20.1 版本。

## 分支

原仓库存在三个分支，分别是 `master`、`1.3.5` 和 `4.0.0`。它们之间的关系是：`master` → `1.3.5` → `4.0.0`，这三个分支是互相继承的，不存在三个分支各玩各的情况（至少我 Fork 的时候是如此）。

但是如果你想修改模组的话，直接从三个分支开始修改可能会无从下手（比如搞不确定 `1.3.5` 和 `4.0.0` 的关系）。因此我们对分支结构进行了重构，具体的分支描述如下：

| 分支           | 支持的 MTR 版本 | 支持的 Minecraft 版本 | 模组版本         | 原始分支                                                                                                                               |
| -------------- | --------------- | --------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| mtr-3.2.2/1.20 | 3.2.2           | 1.20.1                | 1.3.4            | 从原仓库`master`分支（提交`142ba1`）创建                                                                                               |
| mtr-3.2.2/1.16 | 3.2.2           | [1.16.5, 1.19.4]      | 1.3.4            | 从原仓库`master`分支（提交`142ba1`）创建，此分支无需修改，因此仍保留在`142ba1`                                                         |
| mtr-4.0.0      | 4.0.0           | 1.20.1                | 最新版（原仓库） | 从原仓库`1.3.5`分支（提交`faeebe`）创建，然后将原仓库`4.0.0`分支的最新状态压缩为单次提交应用，跳过了 1.3.5 到 4.0.0 之间的所有中间提交 |

（我们尽量让这个分支的命名符合规范，但可能并不适合所有人，我先道个歉喵）

本仓库还启用了 GitHub Actions，你可以从 Actions 页面内下载实时构建好的文件（不过 Release 内也可以）。

## 兼容性

你可能好奇我们是如何使其兼容 MTR 3.2.2 和 Minecraft 1.20.1 版本的。这个事不难，就是工作量比较大。首先，我们修改了 Minecraft API 的调用以适应 1.20 版本，比如方块属性 API（从 Material 改为 MapColor）。其次，我们发现原始的渲染方法不存在了，所以我们改用 MTR API 来渲染。反正主要的工作是改调用，用新的方法来替代。但目前可能还存在一些问题。

目前已经在 1.20.1 版本的 Forge 服务器上测试过（1.18.2 升级 1.20.1），模组可以正常使用（**但也只是可能可能**，如果存在问题还是需要报道的）。我也不能完全确定它几乎接近原版，所以我们建议您在您的服务器上进行测试，并**在升级前备份存档**。

## 构建

1. 克隆这个仓库
2. 执行`./gradlew build`
3. 模组 jar 文件将在`build/release`目录中

如果您遇到网络问题（特别是中国大陆），请尝试配置代理。

如果您使用 Clash 作为代理，您可以按如下方式设置代理，将其添加到`gradle.properties`文件中。您也可以开启 TUN 模式，_但我们建议保持关闭_，只需设置系统代理并在下方设置 HTTP 代理就足够了。（TUN 模式在 gradle 库下载中可能无法完美工作，但下方的代理配置总是有效，所以我们建议保持关闭）

```
# HTTP Proxy
# Clash 默认端口为7890，如果开启了随机端口或设置了其他端口，请相应修改
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7890
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7890
```
